# Live whiteboard with D2

A hand-drawn diagram in a browser tab that redraws each time you save the `.d2` file (about half a second per render).

## Start it

```bash
dir="${TMPDIR:-/tmp}/whiteboard" && mkdir -p "$dir"
# write "$dir/<topic>.d2", then run this in the background (it keeps running):
d2 --watch --sketch --layout elk "$dir/<topic>.d2" "$dir/<topic>.svg"
```

`--watch` prints `listening on http://127.0.0.1:<port>` and opens that page in the browser. Give the user the URL. Every later edit to the `.d2` file redraws the open tab. The process keeps running until stopped; stopping it ends the live updates.

## Check your own render

The browser tab can't be seen from here. After each change:

1. Check the watch output for `err:` lines. A compile error leaves the tab showing the previous render.
2. Screenshot the SVG and look at it:
   ```bash
   chromium --headless=new --hide-scrollbars --window-size=1800,1000 \
     --screenshot="$dir/<topic>.png" "file://$dir/<topic>.svg"
   ```
   Don't use `d2 … out.png`. PNG export downloads Playwright, which can fail.
3. Fix overlapping labels, clipped text and long strips. Expect 2–3 rounds.

## Layout rules

- If the render comes out as a long horizontal strip, switch between `direction: right` and `direction: down`.
- Fold a reply into its request's arrow label (`"POST /x\n← 200 before processing"`). A separate return arrow loops around the whole diagram.
- Number steps with plain `1.` `2.` `3.`. The sketch font has no ①②③ and renders them as "8".
- If an arrow cuts through text, shorten the label or move the text into its own `shape: text` node. Retargeting the arrow to a container usually makes routing worse.
- Reserved words can't be keys: `label`, `shape`, `style`, `icon`, `tooltip`, `near`, `width`, `height`, `direction`, `constraint`. Write `"label (clinic name)": …` instead.
- For a value that contains double quotes, wrap it in single quotes: `slug: 'acme-clinic'`.

## Patterns

Story caption (step 1 of the whiteboard):

```d2
why: |md
  # Checkout: how an order gets paid
  **Goal:** …\
  **Constraint:** …\
  **Consequence:** …\
  **So:** … the **job queue** …
| {shape: text; near: top-center}
```

Privilege or trust zone, stating what it can reach:

```d2
public: "PUBLIC — web API" {
  style.fill: "#eaf5ea"
  can: |md
    - own database only
    - no admin credentials
  | {shape: text}
  handler: "Checkout handler"
}
```

Stored record with example values and sensitive fields marked, one per tenant (stacked):

```d2
store: "one record per tenant" {
  style.multiple: true
  row: "latest version (JSON)" {
    shape: sql_table
    slug: 'acme-clinic' {constraint: routing}
    apiKey: string {constraint: SECRET}
  }
  limits: "Only operations: list by tag · read one. No lookup by field." {shape: text}
}
```

Attacker, not-yet-built parts, and risks:

```d2
attacker: Attacker {shape: person; style.stroke: "#c0392b"}
attacker -> public.handler: "forged request\n→ rejected: bad signature" {style.stroke: "#c0392b"; style.stroke-dash: 3}

future: "Not built yet (TICKET-123)" {style.stroke-dash: 4; style.opacity: 0.5}

risk: "holds every tenant's key in memory" {shape: text; style.font-color: "#c0392b"}
```

Other shapes: `person`, `cloud`, `cylinder` (database), `queue`, `stored_data`.
